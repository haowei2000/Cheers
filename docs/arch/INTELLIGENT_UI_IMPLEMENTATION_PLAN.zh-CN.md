# Intelligent UI 完整实施计划

状态：提案，尚未实施本计划中的新增能力。基线核对日期：2026-10-12。

## 目标与现状

让同一个资源在回复、展开视图和 Workbench 中连续使用。TSX Canvas 提供复杂表达与本地交互，A2UI 提供声明式标准控件，URI 提供身份，宿主负责设备适配和权限边界。保持现有 Rust gateway、MCP 工具、ACP Bot 调度和文件存储链路。

已具备：TSX 编译 worker、隔离 iframe、设计检查与元素定位；A2UI 的受限目录；Desk 回复预览与共享快照；版本化文件写入；A2UI 请求的授权、来源校验与幂等收据；Mac 原生打开。

需补齐：回复内 TSX 执行、回答内容编排、TSX 可验证动作声明、全局资源身份、连续视图状态、设备能力协商、持久执行反馈和多端覆盖。

注意：现有 TSX 的 form.submit/action.trigger 通路主要准备草稿，不能当作已具备与 A2UI 相同的受校验 Bot 请求能力。channel-relative URI 也不是全局 URI。

## 一套架构

模型经 MCP 发现契约 → 写入现有资源 → 在当前回复声明引用 → 统一 resolver 读取并授权 → renderer registry 选择 TSX/A2UI/文本等 lens → Reply/Workbench 宿主选择呈现级别 → 统一 interaction dispatcher → gateway 或原生适配器 → 现有 ACP/任务通路 → 版本化资源更新与状态通知。

资源身份、表现级别、渲染器和动作是独立概念。资源没有新的重复内容仓库；表现级别不生成三份文件；Canvas 不是新的执行后端；URI 不是授权凭据。

## P0：冻结共享契约与迁移边界

前端：以现有 LensProps、ResourceCardContext、快照 store 和 interaction dispatcher 为基础，整理统一 ResourceViewHost。声明 URI、版本、presentation、capabilities、状态接口和只读行为。回复视图不开放设计编辑；Workbench 保留现有编辑能力。

后端：把资源来源及动作校验从 A2UI 专有解析中拆出公共边界；定义带版本的动作声明：稳定 actionId、类型、目标 Bot/URI、输入 schema、可用呈现级别及声明版本。A2UI 从现有文档提取声明；TSX 用可解析的元数据声明。选择现有文件元数据或同一资源包 manifest 的具体落点后再冻结协议，避免独立动作服务和重复事实来源。

模型契约：能力查询返回可用渲染器、schema 版本、呈现和动作约束；只有宿主提供的稳定标识和版本可用于请求。

验收：TSX 与 A2UI 经过同一授权/版本/动作校验；脚本不能声明任意 Bot 请求后直接执行；不改 ACP RPC。旧资源和旧附卡继续可读。契约新增能力通过显式版本协商。

## P1：回复内 TSX Canvas 闭环（首个发布里程碑）

前端：复用 ArtifactLens、编译 worker、iframe bridge 和资源快照；按 renderer registry 分发预览，移除回复对 A2UI 的硬编码。传递 minimal/medium/max 及宿主主题。为 TSX 定义同模块的呈现接口；没有 minimal 实现时提供可读摘要与展开入口，不以截断隐藏必填字段。

实现按需编译、并发上限、来源版本缓存、视口外暂停、iframe 数量预算；错误/超时/不支持时可看摘要或源码。页面隐藏时停止非必要活动。审核 bridge 来源窗口、消息大小、会话标识、CSP 和导航边界；保留 allow-scripts 隔离，不向 iframe 注入凭据。

状态：展开/收起优先保留同一实例；必须换容器时用宿主状态键迁移，不依赖源码重新执行恢复表单。全屏打开继续指向同一资源。

验收：模型经真实 MCP 写 TSX 并附卡；回复内运行一个交互图解、一个表单；展开后输入保留；请求经公共校验进入 ACP，Bot 更新同一资源；非法动作/坏源码有可用降级。消息历史不为所有资源创建运行实例。

## P2：全局 URI 与统一解析

后端：采用稳定服务身份和稳定 resourceId 建立全局引用；当前频道、路径、权限和存储位置由 resolver 解析，URI 字符串不直接暴露机器路径。先完成 ADR，确定服务身份在本地、私有部署和跨服务中的解析方式，再冻结 URI 语法。路径用于易读定位，稳定 id 用于重命名和移动后的身份保持。

定义 workspace/channel/file/attachment/projection 等资源描述、最新版本与固定版本引用、元素定位、删除状态及权限错误。对不可持久投影明确是否能固定版本。跨频道导航先解析目标再鉴权；跨服务第一阶段只明确拒绝或打开受支持链接，不声称具备跨服务授权。

前端：回复与 Workbench 共用 resolver client；缓存按服务/用户/资源/版本隔离，退出登录清理。旧 cheers:desk 相对链接依赖消息原始频道解析；迁移采用读兼容、新写规范，不一次性改写全部历史消息。

验收：跨频道引用、资源重命名、消息转发、原始频道上下文恢复、固定版本查看均有测试；无权限不返回内容；Web/Tauri 解析结果一致。

## P3：回答编排与模型引导

引入版本化回复内容块：文字与资源引用可以交错出现；块引用资源而不复制源码。沿现有消息流增加块标识/顺序及完成语义，明确 partial 与 final 的一致性；旧客户端继续获得正文和附卡降级。

扩展 read_ui_contract：说明何时纯文字、A2UI 或 TSX；提供可运行的比较、图解、模拟和表单范例；要求关键结论有文字摘要。宿主限制高度、密度及系统按钮样式，模型选择语义内容和布局，不决定系统权限或全局主题。

先支持完整资源落盘后插入回复块；真正增量 TSX 编译及 live A2UI 更新另作后续能力，避免流式半份源码反复执行。

验收：比较内容能出现在解释对应位置；选择纯文本不强制生成卡片；可配置简洁呈现；异常资源不阻塞正文；当前 reply id 和 staged cards/blocks 完成事务一致。

## P4：视图状态与操作生命周期

分离三类状态：资源内容（现有版本化存储）、用户视图草稿（按用户/资源/视图/schema 隔离）、操作执行状态（既有任务与请求关联）。图解临时选择默认本地；需刷新恢复的表单采用显式持久策略；跨设备同步需明确用户选择与冲突规则。

提供受限宿主状态 API，只接受有大小/类型限制的 JSON；禁止保存令牌和任意对象。来源更新提示草稿过期，避免无提示覆盖；schema 变化进行声明式迁移或清晰重置。提交携带观察到的来源版本，冲突先刷新并确认输入。

以 invocationId/消息收据关联现有任务，显示已接收、运行、成功、失败及结果 URI；支持取消的任务才显示取消。只有现有任务状态无法承载的动作才新增执行记录。保留当前幂等保留期约束；不宣称外部副作用恰好执行一次。离线默认保存草稿，恢复后显式提交。

验收：重复点击/网络重试不重复派发；刷新和切换视图按策略恢复；资源更新不静默丢输入；接受请求不误显示完成；运行失败可追溯，执行状态改变无需改写 UI 源码。

## P5：桌面与移动端适配

能力协商独立于屏幕尺寸：上报渲染器、原生打开/分享、可用应用、输入方式及只读状态；服务端仍独立授权。TSX 与 A2UI 获得同一能力结果，未支持动作解释原因并给可用替代入口。

桌面：支持键盘焦点、Tab 顺序、快捷打开、窗口恢复；保留本地原件/下载副本区分，检查应用安装与注册根路径。远程桌面操作经有设备身份、用户权限、执行收据的任务路径实现，不通过 URI 直接运行命令。

移动：触控目标至少沿共享 44px 档；处理软键盘、安全区、纵向布局、旋转和长内容；原生分享/文件打开采用平台适配器。SwiftUI/Compose 优先实现标准 A2UI；高表达 TSX 经受控 WebView 复用同一资源和 bridge。不能渲染时仍能查看摘要并打开受支持入口。

设计：正文阅读字体、工具控件无衬线；桌面 minimal 28px、完整视图 36px，触屏 44px；使用设计系统统一控制密度和主题。禁止 generated TSX 任意覆盖宿主工具栏。补暗色、缩放和屏幕阅读器。

验收：Mac/Web/实际支持的移动客户端完成同一资源的查看与提交；平台缺少执行器时动作正确降级；桌面不误打开副本为原件；键盘、读屏、窄屏和触屏检查通过。

## P6：回归、可观测性与发布

保留确定性 ACP fixture 作为链路测试，再用真实支持 HTTP MCP 的 agent 验证模型契约。样例覆盖文字、TSX 图解、A2UI 表单、复杂展开、跨频道引用、本地/远程文件和失败场景。指标包括首个可用预览时间、编译时间、活跃 iframe 数、桥接失败、授权失败、请求/任务关联；日志不记录输入内容或凭据。

测试按边界组织：resolver/auth/版本/幂等契约；bridge 与状态迁移；真实 gateway+MCP+ACP 端到端；Web/Mac/移动视觉及可访问性。性能预算根据现有设备基线测量后制定，避免无依据承诺固定毫秒。

分阶段开关放在同一实现路径：先内部桌面演示，再 Web/Tauri 小范围，再多端。回滚关闭新呈现能力，历史资源保留并提供摘要/Raw/Workbench。涉及 schema 加新 sqlx migration；涉及 connector 变更遵守 Rust connector 发布顺序。更新英文主文档及中文镜像。

验收：第一批样例可复现、故障可定位、旧消息不破坏、开关可回退；单设备执行错误不会阻塞其它资源。

## 实施顺序与完成定义

依赖：P0 → P1；P0 → P2；P1+P2 → P3；状态契约在 P0 定义，P4 在 P1 后落地；P5 的设计和能力契约从 P0 开始，完整多端在 P4 后交付；P6 的验证每阶段持续进行。

第一里程碑只交付 P0+P1：在回复内运行 TSX，保留展开状态，经校验请求 Bot 并更新同一资源。第二里程碑完成全局引用和文字/资源交错回答。第三里程碑完成持久状态、任务反馈和多端。暂不估日期：原生移动现状、任务取消支持及全局服务身份 ADR 核实后再拆任务估工。

全部完成的标准：一份模型生成资源可以从消息引用定位，在回复内使用，展开后状态连续，进入 Workbench 编辑/检查，受授权提交并观察执行结果，更新后所有入口一致；跨频道和设备能力差异都有明确行为，源码与凭据不会越过宿主边界。

## 2026-10-15 实现进展

本分支继续交付 P2/P4/P5 的 Web/Tauri 基础链路：数据库服务身份、稳定资源 ID、
共享全局解析器及保留版本；用户私有草稿 CAS、离线保留和显式冲突选择；绑定活跃设备的
file.open 与真实 PTY terminal.start/input/resize/cancel；可信宿主确认与持久回执。
远程执行复用 workspace RPC，模型仍使用同一资源和动作声明，没有新增 ACP 方法。
详情及边界以 `docs/help/INTERACTIVE_RESOURCES.md` 和中文镜像为准。
跨服务器联邦发现、原生 SwiftUI/Compose 终端、桌面截图/浏览器自动化仍不在本次实现范围。
